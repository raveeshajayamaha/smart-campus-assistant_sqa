# EC4206 Section 3.2 — Software Testing Life Cycle

## Purpose and completion status

The Smart Campus Assistant comprises a React interface, an Express API and a MongoDB persistence layer accessed through Mongoose. The scope includes student and administrator workflows, bearer sessions and a rule-based assistant that reads campus records. The [Section 3.1 test plan](../test-plans/EC4206_Test_Plan.md) defines the testing scope and the [case catalogue](../test-cases/EC4206_Test_Cases.md) specifies the planned checks.

Step 2 established a baseline of **26 passed, 0 failed and 0 skipped** for the existing backend tests. MongoDB connectivity, frontend HTTP availability, direct and proxied backend HTTP checks, ESLint and the production build succeeded. Section 3.2 adds case designs and traceability. TC-001 passed by user confirmation. TC-005 has a partial login observation, and its formal status is Not Run. The other 34 manual cases remain Not Run. The catalogue run passed TC-002 through TC-033. TC-034 through TC-036 have open prerequisites. [Manual results](../test-cases/EC4206_Manual_Execution_Results.csv) · [Automated catalogue results](EC4206_Automated_Execution_Results.md)

## Coverage and remaining gaps

All 14 source-derived or proposed requirements have linked cases. FR-01 to FR-05 cover accounts, sessions, authorisation, profile edits and password changes. FR-06 and FR-07 cover persistence across all five campus collections and schedule validation. FR-08 to FR-10 cover student displays, filtering and assistant responses. QR-01 to QR-04 cover recovery, performance, keyboard interaction and repeatable quality checks.

Detailed coverage can be extended for public event reads versus protected collection reads, each supported assistant topic, every administrator form, concurrent account operations and additional browser and accessibility checks. The existing suites provide related API evidence for some of these behaviours. Backend branch coverage and the hosted CI result are documented. Deployment and frontend test coverage remain unverified. The group must approve performance limits, arrange a peer evaluation and obtain fresh hosted scan evidence for the remaining acceptance cases.
