# [DEF-003] JMeter wrapper exits successfully without a fixture transcript

**Target** `raveeshajayamaha/smart-campus-assistant_sqa`  
**Proposed labels** `bug`, `test-infrastructure` if available  
**Severity / priority** Moderate for evidence completeness / P2  
**Environment** Windows, Node.js 25.6.0, Temurin 17.0.21.1+2, JMeter 5.6.3, disposable loopback MongoDB 8.3  
**Current disposition** Fixed, verified and closed locally. No GitHub closure was recorded.

## Reproduction

1. Use the original checkout-local benchmark wrapper and the Section 3.7 fixture with 100 synthetic events on loopback. Configure one user, a one-second ramp and ten loops.
2. Start the fixture through Node's forked IPC channel, run the event and health samplers, disconnect the IPC channel and inspect the output directory.
3. The original wrapper awaited `once(fixture, "close")` before writing `fixture.txt`.

**Expected** Exit 0, 20 successful JTL rows and a fixture transcript containing startup, preflight and cleanup.  
**Observed** Exit 0 and 20 successful HTTP 200 assertion samples, with no fixture transcript.

The corrected private wrapper replaced the wait with the following completion check:

```js
const exited = Promise.all([
  once(fixture, "exit"),
  require("node:stream/promises").finished(fixture.stdout),
  require("node:stream/promises").finished(fixture.stderr),
]).then(([result]) => result);
```

The corrected replay preserved all 20 successful results and captured the transcript. Retain both transcript and JTL assertions if the wrapper is promoted to maintained test tooling. The historical benchmark metrics are unaffected.
