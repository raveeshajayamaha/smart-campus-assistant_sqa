# [DEF-002] Nested Selenium suite fails before Chrome startup

**Target** `raveeshajayamaha/smart-campus-assistant_sqa`  
**Proposed labels** `bug`, `test-infrastructure` if available  
**Severity / priority** Major for test execution / P2  
**Environment** Windows, Node.js 25.6.0 and Selenium WebDriver 4.41.0  
**Current disposition** Historical fix verified locally.

## Reproduction

1. Anchor Node's module resolver to `backend/tests/ui/selenium.test.cjs`.
2. Resolve the original relative specifier `../server`, as the original suite did when launched through `npm.cmd --prefix backend run test:ui`.

**Expected** The resolver loads the Express entry point and Selenium starts its scenarios.  
**Observed** `MODULE_NOT_FOUND` occurs before Chrome starts because the specifier points to `backend/tests/server.js`.

The fix uses the correct relative depth, such as `../../server`. A fresh resolver probe confirmed both outcomes. The historical rerun passed all five browser scenarios. Add an early module resolution check to avoid committing a browser suite that cannot start.
